# 流程信息图

本目录存放 README 与文档引用的流程信息图。

图片是文档的**可视化摘要**，不是事实来源：图中每一条结论都能在 `docs/` 找到对应正文，
两者冲突时以 `docs/` 正文为准。改流程先改正文，再回来同步配图。

## 二、风格约定

- **版式**：白板手绘风。浅灰底 + 白色纸面 + 黑色粗边框，主标题居中，右上角红色感叹号、左上角蓝色箭头作为点缀。
- **条目形态**：每条是一个梯形斜切条带，内含四部分——线框图标、编号标题、灰色副标题、右侧带小三角指向的标签框。
- **配色**：墨色 `#16181d`、蓝色 `#2f6fd0` 表示正向强调、红色 `#e0402f` 表示禁止项与风险、纸面 `#f6f6f3`、外框 `#d8d8d3`。
- **字体**：`Microsoft YaHei`。Windows 上开箱即用；macOS 或 Linux 需自备等价中文字体，否则字形会变。
- **手绘感的来源**：条带左右端斜切角、标题下划线略倾斜、标签框粗边加右下偏移阴影、箭头用曲线 SVG 而非直线。

## 三、改文案与重新出图

1. 改内容：编辑 `assets/src/<名称>.html`，一张图一个文件，CSS 内联在文件头部，改文案只动正文标签即可。
2. 重新导出 PNG：

   ```bash
   node scripts/build-posters.mjs                     # 全部重出
   node scripts/build-posters.mjs workflow-overview   # 只重出一张
   node scripts/build-posters.mjs --check-only        # 只做排版自检，不写文件
   ```

3. 脚本会先做排版自检：文本溢出条带、或压到右侧标签框，都会打印哪张图的哪一行并返回非 0，
   自检通过才写文件。改动文案后务必跑一次，长标题是该版式最容易踩的坑。

依赖说明：`playwright` 为必需项，`npm i -D playwright` 后执行 `npx playwright install chromium`，
或本机已装 Chrome 时会自动回退使用；`sharp` 为可选项，缺失时输出未压缩 PNG，体积约大 2.5 倍。

## 四、维护约定

- 正文与配图必须一起改，不允许只改一边就合并。
- 单张图片体积控制在 300 KB 以内；超了就调 `--width` 降宽，或改用更少的颜色数。
- 新增图片时：HTML 源放 `assets/src/`，PNG 成品放本目录，并在上面第一节的清单里补一行。
