# 自研技能库

本目录存放**团队自己编写**的技能，是 AI 能力层的主体。

## 技能清单

| 技能 | 用途 | 典型触发语句 |
| --- | --- | --- |
| `flow-orchestrator` | 判断当前处于六阶段哪一步，给出下一步动作 | 「这个任务接下来该做什么」 |
| `impact-analysis` | 反查调用方、记录基线、做回归验证 | 「改这个会不会影响别的地方」 |
| `requirement-intake` | 接收 PRD / 原型，归档原件并逐条标注技术实现 | 「产品给了需求文档和原型图」 |
| `spec-writer` | 把口头需求变成可验收的需求条目与 `spec/` 留档 | 「帮我整理需求」 |
| `dual-axis-review` | 规范轴 + 需求轴的双轴评审 | 「帮我评审这次改动」 |
| `evidence-driven-verification` | 生成可复现的验收证据 | 「验证一下是否真的改好了」 |

## 写作规范

每个技能一个目录，入口为 `SKILL.md`，必须包含 frontmatter：

```markdown
---
name: skill-name
description: 一句话说明什么时候用它（写触发场景，不写实现细节）
argument-hint: "[参数说明]"
---
```

正文结构：何时使用 → 何时不要使用 → 输入 → 步骤 → 输出 → 质量门禁 → 反模式。

六条编写原则见 `docs/03-技能体系.md` 第三节，其中最关键的两条：

1. **不写业务数据**：技能是通用能力，业务规则放 `SPEC.md`。
2. **不写密钥**：任何情况下都不允许。

## 与外部技能的关系

外部引入的技能放在 `.agents/skills/`，来源与哈希记录在 `skills-lock.json`。

**不要把外部技能复制到本目录。** 复制会产生两套各自漂移的副本。需要适配时，在本目录写一个自己的技能，在其中引用外部技能并说明差异。

## 只允许使用仓库内技能

**开发本项目只能使用仓库内技能**：自研在 `skills/`，引入在 `.agents/skills/`。个人目录下的技能（`~/.codex/skills`、`~/.claude/skills` 等）换台机器就不存在，不能作为交付依据。

```bash
node scripts/check-skills.mjs   # 检查技能来源与结构；已接入 npm run validate、pre-commit 与 CI
```

检查项：目录名、缺 `SKILL.md`、front-matter、白名单外的技能、引用仓库外路径、本清单与目录不一致。完整规则与准入流程见 `docs/03-技能体系.md` 第五、六节。

个人技能可以用于探索与一次性试验，但**不得用于交付**；要长期使用就先走引入流程落到 `.agents/skills/`。

## 新增技能的流程

```text
提案 → 试点（真实任务用 2 次）→ 评审 → 发布 → 使用满 1 个月后复盘
```

完整流程见 `docs/03-技能体系.md` 第四节。
