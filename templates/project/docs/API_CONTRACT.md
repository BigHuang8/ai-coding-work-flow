# 接口契约

> 本文件是接口的**唯一权威来源**。改造或新增接口前必读，改完必须同步更新本文件。
>
> 占位内容请按项目实际情况替换后删除本段。

## 一、统一响应外壳

所有接口返回统一结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "a1b2c3d4e5f6"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | integer | 0 表示成功，非 0 表示业务错误 |
| `message` | string | 面向使用者的提示，可直接展示 |
| `data` | object / array / null | 业务数据 |
| `traceId` | string | 链路标识，用于排查；必须回显到日志 |

规则：

1. HTTP 状态码只表达传输层语义，业务结果一律看 `code`。
2. `data` 为空时返回 `null`，不返回 `""` 或 `{}` 混用。
3. 分页数据放在 `data` 内，元数据不放到顶层。

## 二、错误码

- 错误码为 **6 位数字**，禁止使用裸数字码（如 `1`、`500`）。
- 唯一事实来源：`<ErrorCode 定义文件路径>`。新增错误码必须先在该文件登记。
- 前端使用的错误码必须与后端一致，镜像位置：`<前端错误码文件路径>`。

| 区间 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1xxxxx` | 通用错误（参数、权限、系统） |
| `2xxxxx` | 业务模块错误 |
| `9xxxxx` | 第三方集成错误 |

示例：

| 错误码 | 含义 | 提示文案 |
| --- | --- | --- |
| `100001` | 参数校验失败 | 请求参数不合法 |
| `100401` | 未登录或登录已过期 | 登录已过期，请重新登录 |
| `200001` | 客户不存在 | 客户不存在或已被删除 |

## 三、分页

### 入参

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `page` | integer | 页码，从 1 开始，默认 1 |
| `pageSize` | integer | 每页条数，默认 20，最大 100 |
| `keyword` | string | 可选，模糊搜索关键字 |

### 出参

```json
{
  "code": 0,
  "data": {
    "list": [],
    "total": 137,
    "page": 1,
    "pageSize": 20,
    "pages": 7,
    "extra": {}
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `list` | 当前页数据 |
| `total` | 总条数 |
| `page` / `pageSize` | 回显实际生效的分页参数 |
| `pages` | 总页数 |
| `extra` | 附加元数据（统计值等），没有则不返回 |

## 四、TopN 接口

榜单类接口统一使用 `limit` 参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `limit` | integer | 取前 N 条，默认 10，最大 50 |

## 五、导出接口

| 约定 | 说明 |
| --- | --- |
| 导出类型 | 同一接口支持 `csv` / `xlsx`，通过 `format` 参数区分 |
| 返回方式 | 文件流，`Content-Disposition` 带文件名 |
| 文件名 | `<业务名>_<YYYYMMDDHHmm>.csv` |
| 上限 | 单次导出不超过 `<N>` 条，超出时返回明确错误提示 |
| 大数据量 | 超过上限的导出走异步任务，返回任务 ID |

## 七、契约测试

改造或新增列表接口时，必须补充契约测试：

| 检查项 | 说明 |
| --- | --- |
| 响应外壳 | `code` / `message` / `data` 字段齐全且类型正确 |
| 分页字段 | `list` / `total` / `page` / `pageSize` / `pages` 齐全 |
| 空数据 | 无数据时返回空数组与 `total=0`，不抛异常 |
| 错误码 | 错误场景返回登记过的 6 位错误码 |

测试命名：`<模块>ContractTest.java` / `<模块>.contract.spec.ts`。

## 八、变更流程

1. 改契约前先在 PR 中说明影响面：哪些端、哪些页面、是否需要兼容期。
2. 破坏性变更必须提供过渡方案（双写、版本号、灰度开关）。
3. 改完契约后同步更新：本文件、两端类型定义、契约测试、`SPEC.md` 相关条目。
