# 需求规格说明书

> 本文件是<项目名>需求的**唯一权威来源**。与 PRD、聊天记录、旧文档冲突时，以本文件为准。
>
> 写法规范见 `docs/04-上下文与记忆治理.md`（注入模板后该文件位于项目 docs 目录）。

## 使用说明

- 一个模块一个二级标题，一条需求一个四级标题。
- 每条需求必须包含：需求描述、验收标准、范围外、关联 `spec/` 需求目录。
- **验收标准必须可判定**：「体验流畅」不是验收标准，「首屏渲染 < 1 秒」才是。
- 需求变更直接改本文件，并在 `MEMORY.md` 记一行变更原因与日期。

## 模板

```markdown
### 1.1 <功能名>

- 需求：<一句话说明要做什么>
- 验收标准：
  1. <可判定的条件 1>
  2. <可判定的条件 2>
- 范围外：<明确不做什么>
- 依赖：<依赖的其他模块或外部系统，没有则写「无」>
- 关联：spec/<YYYYMMDD>-<主题>/
```
