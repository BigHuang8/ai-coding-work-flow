# 数据库目录说明

本目录承载表结构变更脚本。**完整规范见 `docs/15-数据库设计与建表规范.md`**，此处只写目录约定与操作步骤。

## 一、目录结构

```text
db
├── migration                                 变更脚本（只增不改）
│   └── V202609241530__order_add_pay_channel.sql
└── 建表模板.sql                               复制用模板，不参与执行
```

## 二、脚本命名

```text
V<YYYYMMDDHHmm>__<英文短描述>.sql
```

示例：`V202609241530__order_add_pay_channel.sql`、`V202609250930__customer_add_team_id.sql`

规则：

- `V` 前缀 + 时间戳（按创建脚本的实际时间），保证执行顺序唯一且可读。
- 描述用小写英文与下划线，能看出改什么。
- **一个脚本只做一件事**：加字段与加索引不要混在一个脚本里。
- 已执行过的脚本**禁止修改**；改了要新增一个修正脚本。

## 三、脚本头部必填注释

```sql
-- 目的：新增订单支付渠道字段
-- 影响表：biz_order
-- 预估耗时：< 1 秒（新增可空列）
-- 回滚方式：ALTER TABLE biz_order DROP COLUMN pay_channel;
-- 关联需求：spec/20260924-订单创建/需求与技术对照.md
```

## 四、执行步骤

1. 本地库执行并验证（含回滚脚本演练）。
2. 测试库执行，跑通相关接口与回归用例。
3. 预发环境执行，按 `docs/12-影响面与回归防护.md` 做回归对比。
4. 生产窗口执行，执行后校验数据与索引生效情况。
5. 执行记录与截图归档到 `docs/verification/<日期>-<主题>/`。

## 五、禁止事项

- 禁止直连生产库手工改表后再补脚本。
- 禁止在业务代码里建表、改表或执行 DDL。
- 禁止修改已执行的历史脚本。
- 禁止一次脚本包含多个不相关变更（出问题无法单独回滚）。
- 禁止把生产数据导出到本地或提交入库。
