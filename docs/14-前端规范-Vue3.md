# 前端规范：Vue 3 + TypeScript + Vite

本文件是前端代码的**唯一规范来源**，覆盖 Vite 管理后台（Vue 3 + Element Plus）与 H5 / uni-app 移动端。项目可覆盖，但必须写明差异与理由。

配套文档：[13-后端规范-Java-Spring](13-后端规范-Java-Spring.md)（接口契约的另一端）、[10-技术栈适配](10-技术栈适配.md)、[12-影响面与回归防护](12-影响面与回归防护.md)。

## 一、技术基线

| 项 | 约定 |
| --- | --- |
| 框架 | Vue 3.4+，统一 `<script setup lang="ts">` 组合式 API |
| 语言 | TypeScript 5.x，`strict` 开启，**禁止 `any`**（必要时用 `unknown` + 类型收窄） |
| 构建 | Vite 5.x |
| 状态 | Pinia，只放跨页面共享状态 |
| 路由 | Vue Router 4，路由懒加载 |
| UI | 管理后台 Element Plus；移动端 uni-app 组件 |
| 请求 | 统一封装，禁止组件内裸调 |

依赖变更：新增第三方库前先评估体积与维护状态（能用现有能力实现就不引库）；`package-lock.json` 必须提交，且**只能由包管理器生成**，冲突时重新安装而不是手工合并。

## 二、目录结构与职责

```text
src
├── api
│   ├── request.ts        统一请求实例、拦截器、错误处理
│   ├── types.ts          响应外壳 / 分页 / 错误码类型（唯一来源）
│   └── modules/          按业务域声明接口
├── components
│   ├── common/           通用组件（TablePage、字典选择器等）
│   └── <域>/             业务组件
├── composables/          组合式函数（useTableQuery 等）
├── views/                页面，按模块分目录
├── stores/               Pinia
├── router/               路由与守卫
├── styles/               变量、主题、全局样式
├── utils/                纯函数工具
└── directives/           自定义指令（权限等）
```

职责边界：`api/` 只声明接口与类型，不放业务判断；`views/` 只做页面编排；能复用的逻辑放 `composables/`，不要复制粘贴到第二个页面。

## 三、组件规范

- 文件名 `PascalCase.vue`；页面入口用 `index.vue`（放在 `views/<模块>/<页面>/`）。
- 单文件组件顺序固定：`<script setup>` → `<template>` → `<style scoped>`，便于统一阅读。
- 类型化接口：

```vue
<script setup lang="ts">
interface Props {
  orderId: number
  readonly?: boolean
}

const props = withDefaults(defineProps<Props>(), { readonly: false })
const emit = defineEmits<{ submitted: [id: number]; cancelled: [] }>()
const visible = defineModel<boolean>('visible', { required: true })
</script>
```

- **禁止直接修改 props**，通过 `emit` 或 `defineModel` 回传。
- `v-for` 必须有稳定 `key`（用业务 ID，禁止用 index，除非列表纯静态）。
- 禁止在同一元素上同时使用 `v-if` 与 `v-for`。
- 组件超过约 300 行或承担两件事时必须拆分。
- 通用组件放 `components/common` 并写清 props / emits；业务组件不要跨模块乱放。
- 受控组件（弹窗、抽屉）统一 `visible` 双向绑定，`open/close` 逻辑写在父组件。

## 四、组合式函数

- 命名 `useXxx`，返回对象而不是数组（便于按需扩展）。
- 副作用必须清理：定时器、事件监听、请求在 `onUnmounted` 中释放。
- 请求类 composable 统一处理 loading / 错误 / 分页，例如列表页一律走 `useTableQuery`。
- 不在 composable 里直接操作 DOM 或组件实例，保持可测试。

## 五、状态管理（Pinia）

- 只放跨页面共享状态（登录用户、字典缓存、全局配置）；页面内部状态用 `ref`。
- 文件 `stores/<域>.ts`，导出 `useXxxStore`。
- 持久化必须显式声明字段，**禁止把 Token 之外的用户敏感信息写入 localStorage**。
- store 只暴露 `state` / `getters` / `actions`，禁止在 store 里操作路由或弹出 UI。

## 六、接口层

- 所有请求经 `api/request.ts`，统一处理鉴权头、超时、错误码、登录失效跳转。
- 响应类型统一取自 `@/api/types`（`ApiResponse` / `PageResult` / `ErrorCode` / `ApiError`），**不得重复定义响应结构**。
- 业务模块只声明接口与出入参类型，示例：

```ts
export interface OrderQueryReq {
  page: number
  pageSize: number
  status?: OrderStatus
}

export function queryOrderPage(params: OrderQueryReq) {
  return request.get<PageResult<OrderVO>>('/api/admin/orders', { params })
}
```

- 禁止在组件里裸调 `fetch` / `axios`，也禁止在组件里拼 URL。
- 重复提交防护：按钮 loading + 请求中标记；必要时取消上一次请求。
- 下载、上传、导出统一封装，避免每个页面各写一遍。
- 前端校验只为体验，**后端才是权威**；错误提示必须展示后端消息。

## 七、路由与权限

- 路由一律懒加载：`component: () => import('@/views/...')`。
- `meta` 中声明 `title`、`requiresAuth`、`permission`，菜单与面包屑由 `meta` 生成，不手写重复配置。
- 按钮级权限用指令或权限函数统一判断，禁止在模板里散写角色字符串比较。
- 路由守卫只做登录态与权限判断，不做业务请求；页面刷新后要能恢复用户信息。
- 404 / 无权限页面必须有明确出口（返回首页或提示联系管理员）。

## 八、样式规范

- 2 空格缩进；`<style scoped lang="scss">`。
- 类名 `kebab-case`；嵌套不超过 3 层，避免生成难以覆盖的选择器。
- 颜色、间距、字号统一用 `styles/variables.scss` 中的变量，禁止散落魔法值。
- 禁止行内样式（动态计算的尺寸除外）。
- 图标、主题、暗色模式统一入口，不混用多套图标库。
- 移动端适配方案（rem / vw）全项目统一，并处理刘海屏安全区。

## 九、列表页与表单页（管理后台统一模式）

- 列表页统一使用 `TablePage` + `useTableQuery`，**禁止**页面内手写 `el-table` + `el-pagination` 组合。
- 查询条件、分页、排序参数结构统一，便于复用与后端契约对齐。
- 表格必须有：加载态、空数据文案、操作列固定、超长文本省略 + 悬浮查看。
- 表单校验规则集中在 `rules`，与服务端规则保持一致（字段名、长度、必填）。
- 弹窗表单关闭前二次确认（有未保存内容时），提交成功后统一刷新列表。
- 导出、批量操作等重行动作必须二次确认，并展示执行结果。

## 十、性能与体验

- 首屏：路由懒加载、组件按需引入、图片压缩与懒加载。
- 长列表用分页或虚拟滚动，禁止一次性渲染上千行。
- 高频事件用防抖 / 节流（搜索输入、滚动、resize）。
- 慎用深监听 `watch(..., { deep: true })`，大对象会造成性能问题。
- 每个请求都要有 loading 或骨架屏，避免白屏与重复点击。
- 新增依赖前评估打包体积，避免为一个小功能引入整套库。

## 十一、常见反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 组件内直接发请求并拼 URL | 接口散落，改一次全项目搜 | 收敛到 `api/modules` |
| 复制粘贴第二个页面的逻辑 | 逻辑分叉，修一处漏一处 | 抽到 `composables` |
| 用 `any` 消掉类型错误 | 类型形同虚设 | 定义接口或用 `unknown` + 收窄 |
| 直接改 props | 数据流不可追踪 | `emit` / `defineModel` |
| 响应结构各页面自定义 | 后端改外壳时全线崩 | 统一 `api/types` |
| 只在按钮上加 `loading` 不防重 | 重复下单 / 重复提交 | 提交标记 + 后端幂等 |
| 手写表格分页 | 样式与行为不一致 | 统一 `TablePage` |
| 把大对象放 store 持久化 | 本地存储膨胀且难清理 | 只持久化必要字段 |
